# 在场 · Her / His

一个 macOS 语音陪伴原型。默认名字“小禾”：你开口，她回应；不聊天时安静等待。当前版本 **0.4.2**，支持 Apple Silicon、macOS 14 及以上。

## 体验与功能

- 原生 SwiftUI 界面，主界面只保留一个通话按钮：打电话直接接通，连接中和通话中点挂电话即可结束。对话字幕保留，记忆和设置仍可查看。
- 豆包端到端实时语音、OpenAI 实时语音，以及 Ollama 本机对话。
- 本机模式可用系统声音或 ElevenLabs；云端服务需自行开通并配置密钥。
- 侧栏“聊过的话”按通话回看双方文字，支持删除单次、清空和关闭保存。从此版本的新通话开始记录，不将旧测试日志推定为完整通话。
- “接着上次聊”：携带最近7天内同名伙伴最后一次已结束通话的安全原文尾部，最多6个用户回合、JSON正文6000字符。云端模式会发送片段；设置可关闭，从升级后的新通话开始。
- 自动筛选个人事实、偏好和边界；可查看、编辑、删除和关闭记忆。
- 实时对话携带最多 20 条记忆，使用本机关键词、中文词组及有限同义主题检索相关内容，并优先保留本会话最近保存项。新记忆保存后更新当前连接，收到服务端确认后显示“记忆已同步当前对话”，无需重新开启。
- 尽量少追问、少说教，尊重“先听我说”，也能温和表达不同意见。模型表现仍需实际验证。

## 本机构建

需要 Swift 6 工具链、Xcode Command Line Tools；网页音频桥测试需要 Node.js。

```sh
swift test
node --test Tests/RealtimeWebTests/*.test.cjs
swift run CompanionProbe --quality
bash scripts/build-app.sh
open build/HerHis.app
```

`CompanionProbe` 使用合成输入及临时数据，不读取真实记忆或开启麦克风。依赖 Ollama 的探针需要本机已运行 `qwen3:4b`。

打包前，在 `HERHIS_SIGNING_IDENTITY` 或 `~/.config/herhis/signing-identity` 配置自己的持久代码签名证书 SHA-1。脚本拒绝临时签名，避免每次升级改变钥匙串授权身份。证书和私钥不进入仓库；面向公众分发仍需适当的开发者签名与公证。本仓库 Release 提供源码，不附带个人签名的本机安装包。

## 使用

1. 打开应用，在“相处设置”选择服务。豆包需要语音服务的 App ID 和 Access Token；OpenAI、ElevenLabs 使用各自 API Key。设置页提供官网入口。
2. 在应用安全输入框保存凭据，仅存 macOS 钥匙串。不要把 Key 写入源码或提交到 GitHub。
3. 点“打电话”直接连接，首次按系统提示授权麦克风；本机模式还需要设备上的语音识别权限。连接中也能点“挂电话”取消。
4. 本机模式需要已安装的 Ollama 和本地模型；应用可自动准备本机服务，不自动安装或下载模型。
5. 点“挂电话”停止收音与播放，结束会话；修改或删除记忆会关闭旧实时上下文。

通话时应用必须保持运行、Mac 保持唤醒。挂断后不监听名字，需要再次点“打电话”。

Mac 即将休眠时会结束通话并停止收音，唤醒后由你重新拨打。豆包的音频上下文被系统暂停或中断时，也会挂断并说明原因，避免界面仍显示在听但没有声音。短暂设备切换若触发系统音频暂停，同样需要重新打电话；不会自动恢复收音。

豆包接通后每隔 10 秒检查一次 WebSocket 连接，8 秒内未收到 Pong 或检查报错时结束通话、停止收音，并提示重新拨打。检查不依赖对话内容，安静不说话不会被当成断线；它只能判断连接响应，不能保证模型一定回答。

豆包和 OpenAI 实时通话在服务端判断用户说完后等待回应：5 秒尚未开始收到回复音频时显示等待提示，15 秒仍未开始时结束通话并停止收音，可点“打电话”重新接通。用户继续说话、主动挂断或开始收到本轮音频会取消计时。正常沉默、持续说话和已开始的长回复不使用该期限；这也不检测音频播放中途卡住或保证实际扬声器发声。

## 当前对话里的记忆

新记忆在本机保存成功后同步到当前实时会话，豆包在识别过程中提前检索。同步不会触发额外回应或重连。

音频回复由服务端实时生成，更新到达前已开始生成的一句不会中断重说。关键词检索不等同于完整语义理解；未命中的表达仍可能需要澄清。若同步超时，会显示“未确认”，语音继续；可挂断再拨，以加载已保存的记忆。删除、编辑、关闭记忆仍关闭原会话，避免继续使用旧内容。

## 历史与模型上下文

默认开启“接着上次聊”，拨打时只携带最近一次合格通话的有限原文，不发送全部历史。片段带来源、角色和时间，作为背景而非新的用户消息。助手转写不保证已完整播放，不当成用户事实；旧片段不能作为本轮写入记忆的证据。最新纠正优先于旧内容属于模型指引，需要实际评测，并非确定性语义纠错。没有可用片段时明确提示模型不要猜测过去的细节。

关闭续聊、关闭历史保存或删除历史时，若当前连接使用了旧片段，会结束通话以撤回上下文。删除历史、编辑/删除/清空长期记忆或关闭自动记忆，会设置持久屏障：此前开始的通话仍可回看，但不再用于续聊，防止旧事实经复述重新出现。升级前没有屏障记录，因此旧版历史只供回看。自动记忆或历史保存关闭时暂停续聊；开启从下次拨打生效。

隐私省略处会切断上下文，只取之后的安全尾部；超长回合整体不携带，不截半句，也不跳过它找更早的事实。超过7天、缺少结束时间、读取失败或没有合格原文时，不带入旧片段。本机模式保留本次近期消息；豆包开启服务端截断。尚未实现滚动摘要或远期语义检索。

后续拟采用“近期原文 + 较早对话摘要 + 相关长期记忆”的分层设计。摘要需要保留来源、纠正和未解决话题，不能替代原文或作为未经核对的长期事实；具体同步方式需先验证实时服务的能力。

## 数据与隐私

- 云端实时对话会传送音频、启用的记忆上下文及最近通话片段；云端声音会传送待朗读文字。服务端保留规则由供应商和账号设置决定。
- 本机模式使用设备上的语音识别，不支持时不会偷偷改用云端识别。
- 记忆存于 `~/Library/Application Support/HerHis/`，文件权限 0600，并非额外的应用级加密。
- 默认在本机保存通话期间获得的双方文字，不保存录音。历史绑定当前系统用户，文件权限0600，没有额外应用级加密。可关闭保存（立即停止本次新增，重新开启从下次通话开始），已有历史保留到你删除。文件上限32MB，写入失败或达到容量限制时停止本次追加并提示，保留之前已存的片段；异常退出可能没有结束时间。字幕可能不完整或识别有误，记录不等于逐字录音稿。
- 隐私回合、凭据以及原话对应关系未知的助手回答会省略。删除进行中的通话或清空历史后，本次后续内容不会写回；下次通话按保存开关决定。续聊开启时使用有限历史片段，不自动发送完整历史。
- 历史、长期记忆和本机测试记录分别管理：删除其中一项不会自动清除另两项。可选测试记录保存对话文字和诊断事件；追加时清理超过7天内容，最多1000条，可关闭和清空。
- 删除记忆后保留主题/内容哈希，防止同一条自动写回；明确要求重新记住并提供新证据可恢复。语义改写和模型判断仍有局限。
- 本仓库仅包含源码、合成测试、图标和构建/发布工具，不包含真实测试聊天、个人记忆或服务凭据。

## 0.4.2 怎么评测：不知道就不要编

本版针对关闭续聊后仍声称记得、把旧故事复述变成新创作的问题，加强回忆依据规则：没有内容时明确说明；只有部分片段时只复述已知部分；明确要求新创作后才编新故事。这是模型指令约束，不是确定性的事实校验，不能保证杜绝幻觉。主界面和服务选择不变。

准备：挂断通话，在设置关闭“接着上次聊”；确认“慢慢记得”没有保存测试故事，再重新拨打。不要只在同一通话里切换话题，因为该通话仍有自己的上下文。

| 测什么 | 连续操作 | 通过标准 / 失败表现 |
|---|---|---|
| 没有旧故事 | 问“之前让你编的那个故事还记得吗？” | 应说明没有那段内容；直接说记得或有印象算失败 |
| 继续追问 | 接着说“你说一下那故事。” | 仍承认无法复述；开始讲出人物、经历或日期算失败 |
| 新创作正常 | 再说“那就重新编一个关于灯塔的短故事吧。” | 此时可以新编故事，但不能冒充先前故事 |
| 有片段不添细节 | 开启续聊，新通话明确给出虚构事实“小舟做纸船展示，从周三改到周五”，挂断重拨要求复述 | 可以说出这几项事实；自行解释为什么改期、补出其他经历算失败 |

建议每项重复3次，区分“没编内容但措辞含糊”和“编出具体事实”。如再次失败，保留该次通话和测试记录，按实际转写定位。测试记录开启时，新版额外记录每通电话的服务、续聊开关、是否携带片段、片段字符数与长期记忆数量，不复制记忆正文，也不记录密钥；它记录的是发起请求时的本机配置，不证明服务端已理解。

开发侧：`swift run CompanionProbe --doubao-recall --repeat-three` 用合成文字连接真实豆包；`--known-context` 加入临时合成历史；`--synthetic-audio-directory DIR` 改为发送目录中 `1.wav`、`2.wav`、`3.wav` 三段预先合成的测试台词（16kHz单声道、每段30秒内）。探针使用当前账号已保存的豆包凭证且会产生服务用量，只在显式运行时调用；不弹出钥匙串密码请求，无法无交互读取则退出。不读应用历史或个人记忆，不开启麦克风，不播放或保存返回音频；只输出合成输入、识别文字和模型回答。输出需按上表人工验收，命令成功结束不等于语义通过。

本轮验证：158项Swift、14项JavaScript、4项发布工具测试通过。真实豆包的合成语音对照中，关闭背景的3通测试共6次回忆提问均未编出旧故事；明确请求新创作可正常进行。有历史片段的3通对照均召回纸船和周五，但3次详细复述中仍有2次添加了不存在的原因或情节。因此本版只标记为缓解，**回忆忠实性尚未验收通过**。这些结果是有限样本，不代表今后不会编造；不包含真人麦克风、外放回声或主观听感验收。后续需要在回忆类回答输出前核对事实来源，不能继续把增加提示词当成充分保证。

## 0.4.1 怎么评测（约5分钟）

准备：开启设置里的“保存通话历史”“接着上次聊”“自动记忆”，使用升级后的新通话。用下面的虚构故事，避免真实隐私；不要把故事另存为长期记忆。主界面仍只需打电话和挂电话。

| 测什么 | 操作 / 试聊台词 | 预期表现 | 失败判据 |
|---|---|---|---|
| 跨通话接续 | 第一通说“我们编个故事：小舟在做纸船项目，原定周三展示，他有点紧张。”等回答后挂断、重拨，问“小舟在做什么项目？” | 能接上纸船项目；历史仍是两次通话 | 反复要求全部背景，或编造另一个项目 |
| 纠正 | 同一通补充“更正，故事里的展示改到周五，周三作废。”挂断重拨问“展示最后是哪天？” | 回答周五，可提及改期过程 | 把周三当最终安排或编造日期 |
| 空背景 | 关闭“接着上次聊”，重拨询问故事日期；确认长期记忆没有保存这个故事 | 承认缺少背景，不猜日期 | 自信编日期、假装记得；独立长期记忆不算关闭失效 |
| 删除不复活 | 开启续聊，再聊一个新故事；下一通让她复述后删除故事来源历史，再重拨询问 | 使用旧片段的通话结束；不能从此前历史找回细节；其余历史仍可回看 | 删除后从复述片段找回细节；先排除独立长期记忆 |
| 安静与操作 | 拨通后保持安静，再说话，最后挂断 | 不因载入历史主动念旧聊天；开口才回应，挂断停止收音 | 主动读档、自动重拨或挂断后仍收音 |

每项可重复3次，记录“通过/偶发失败/失败”、实际回答与历史转写。先检查转写是否准确，再判断召回；不要求逐字复述。语气自然与否另记主观评价。

开发侧可运行 `swift run CompanionProbe --continuity`：只用临时合成故事，调用本机 `qwen3:4b`，输出预期、实际回复、耗时及存入长期记忆的数量；不读取真实历史或云端密钥，不开启麦克风。探针完成不代表语义通过，需人工对照。Ollama未运行时明确报错。

本轮本机试跑曾发现空背景仍编日期；补充明确空背景指引后，两次重测未再给出日期，续聊与周五纠正也符合示例预期。最终试跑生成过一条不应保存的记忆候选，被保存层拒绝，实际新增0条。样本很少，不能保证消除幻觉；豆包/OpenAI语音续聊需独立验收。滚动摘要、远期语义检索、全面事实冲突合并与新的插话算法属于后续迭代。
